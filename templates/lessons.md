# Mission Lessons

Copy to .mission/lessons.md or use the established shared store. Read relevant
prior entries BEFORE contract drafting. Keep at most two lessons per mission;
zero is valid. Replace this example section rather than preserving placeholders.
On resume, update that mission's entries; preserve other missions' lessons.

## <stable-mission-id> — <task class>

- **Task tags / last checked**: searchable task terms and evidence date.
- **Context**: conditions under which the lesson applies.
- **Observation**: what actually succeeded or failed.
- **Evidence**: artifact/checkpoint/decision-log reference.
- **Reusable lesson**: one correction that changes a future decision.
- **Future verify criterion**: an observable check incorporating this lesson.

For non-done exits, record the brief retrospective in the decision log. Do not
add a lesson merely to fill a quota or include credentials or sensitive output.

For shared stores, read the current base with store-read, merge into a separate
proposal, then use store-publish with that base hash. On conflict, reread and
merge; do not force overwrite. See references/reliability-patterns.md.
